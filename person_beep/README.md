# Freenove ESP32-S3 person detection + GPIO14 double beep

Standalone ESP-IDF project with **real PicoDet INT8 person detection running entirely on the board**. No Wi-Fi, Mac inference server or internet is needed at runtime; network is only required the first time build dependencies are installed. The old `../ESP32_USB_Camera.ino` code is unchanged; only its comments were translated to English.

## Confirmed hardware and dependencies

Read over serial in this round: ESP32-S3 rev v0.2, **8MB Flash, 8MB embedded PSRAM**. The connection is a CH343 USB-UART (VID:PID `1A86:55D3`), not native USB CDC.
The actual camera on this board reads as **GC0308, PID `0x009B`**. The OV3660 in old notes was not treated as the current sensor; always trust the boot log after changing modules.

| Dependency | Pinned version |
| --- | --- |
| ESP-IDF | **v5.4.2**, commit `f5c3654a1c2d2a01f7f67def7a0dc48e691f63c0` |
| ESP-DL | **3.3.6** |
| esp32-camera | **2.1.3** |
| dl_fft / esp_new_jpeg / esp_jpeg | **0.8.0 / 1.0.2 / 1.3.2**, see `dependencies.lock` |
| Local Python / cross compiler | **3.13.7 / esp-14.2.0_20241119** |
| Model | pedestrian_detect **PICO_S8_V1**, 435,328 bytes, included |

Model download, SHA256, license and upstream implementation are in [models/README.md](models/README.md). There is no model conversion step.
Do not delete `dependencies.lock`; it pins all transitive dependencies.

## GPIOs and image

Based on the `ESP32S3_EYE` pin branch in [Freenove's official camera_pins.h](https://github.com/Freenove/Freenove_ESP32_S3_WROOM_Board/blob/main/C/Sketches/Sketch_07.2_As_VideoWebServer/camera_pins.h); the branch name only indicates the same wiring, and **the board is still a Freenove ESP32-S3 WROOM**.
The original camera program is not preserved in this directory, so the official pin table is not passed off as old local code.

| Function | GPIO |
| --- | --- |
| Active buzzer | **14, HIGH = beep, LOW = silent** |
| XCLK / PCLK | 15 / 13 |
| SCCB SDA / SCL | 4 / 5 |
| VSYNC / HREF | 6 / 7 |
| D0..D7 | 11, 9, 8, 10, 12, 18, 17, 16 |
| PWDN / RESET | -1 / -1 |

The tested GPIO14 → 1kΩ → S8050 → TMB12A05 circuit is kept. The camera and GPIO14 do not conflict.
Camera: 10MHz XCLK, RGB565BE 320×240, two PSRAM buffers, latest frame; the model resizes to 224×224.
The sensor PID is read at boot; currently GC0308, and the driver also supports OV3660 (`0x3660`), OV2640/OV5640. Vertical flip is enabled by default; if the module is mounted differently, change `set_vflip/set_hmirror` in `main/app_main.cpp`.

## Building and flashing on macOS

**Open the whole `person_beep` folder in VS Code**, not a single `.cpp`.
`.vscode/tasks.json` is provided: **⌘⇧B** builds, **Terminal → Run Task → ESP32: Flash** flashes, **ESP32: Serial Monitor** opens the serial monitor; enter the actual port.
These tasks call the configured ESP-IDF directly, so no extra VS Code extension is needed to build. If the Microsoft C/C++ extension is installed, the editor reads `build/compile_commands.json` generated by this project for code completion.
VS Code is the editor; the actual build is done by **ESP-IDF v5.4.2 + Xtensa GCC**.
If you later want the official Espressif VS Code extension, see the [official integration guide](https://docs.espressif.com/projects/vscode-esp-idf-extension/en/latest/); the three tasks provided here already build, flash and monitor directly.

The local machine already has the toolchain installed and has completed builds. Open a terminal:

```sh
cd person_beep
bash scripts/test.sh
bash scripts/build.sh
ls /dev/cu.*
bash scripts/flash.sh /dev/cu.usbmodem5C930528211
bash scripts/monitor.sh /dev/cu.usbmodem5C930528211
```

Exit the monitor with **Ctrl+]**; do not open Arduino Serial Monitor and another serial tool at the same time.
You can also select the port and **115200 baud** in the Arduino IDE Serial Monitor and press RESET to see the boot log.
This project uses native ESP-IDF ESP-DL and **cannot be compiled as a `.ino` in the Arduino IDE**.

First build on another Mac:

```sh
brew install python@3.13 cmake
xcode-select --install  # only if Command Line Tools are not installed
cd person_beep
bash scripts/setup.sh
bash scripts/build.sh
```

Or `source scripts/env.sh` and manually run `idf.py build`, `idf.py -p PORT -b 115200 flash monitor`.
The default IDF installation directory is `~/.espressif/esp-idf-v5.4.2`; scripts do not depend on the system default Python 3.15.
Full readback at 460800/921600 caused serial corruption on this CH343 link, so 115200 is the default; flashing takes several minutes.
If automatic download mode fails: hold BOOT, press and release RESET, release BOOT, then retry flashing.

The default flash header matches the measured **8MB**, but partitions use only the first 4MB, with an application partition of 0x3f0000 and no OTA.
Check capacity on another board first with `python -m esptool --chip esp32s3 -p PORT flash_id`.
If a board really has only 4MB, set Flash Size to 4MB in `idf.py menuconfig` and rebuild; an 8MB header on a 4MB board fails before the application starts.
Boot also prints and checks PSRAM capacity and the largest contiguous free block; this version requires at least 4MB of working OPI PSRAM.

## Detection, alerting and error handling

- Only the single-class model's `category=0` is person; NaN/invalid boxes and low scores are filtered. Threshold **0.80**, NMS **0.50**, at most 10 boxes. An early test observed a low-scoring candidate around 0.704, so the default threshold was raised.
- Serial prints `box=[x1,y1,x2,y2]` in 320×240 image coordinates. This version has no LCD/web preview or pixel segmentation.
- The **RMT peripheral** produces HIGH 200ms → LOW 200ms → HIGH 200ms → LOW. The CPU does not wait for those 600ms.
- GPIO14 also enables input readback; `BUZZER_PIN` prints actual pin HIGH/LOW changes with microsecond timestamps for waveform inspection, but it cannot replace human hearing.
- A 5ms alert task on CPU0 starts/cancels sequences and handles cooldown; CPU1 runs inference. After the completion callback it waits **at least 2000ms LOW**, so consecutive detections start a new sequence at least about **2.6 seconds** apart.
- If no person is present, the result is older than **1.5 seconds**, or capture fails, the current alert is cancelled without queueing a retry. RMT has already written the complete short waveform to hardware, so one slow inference cannot stretch HIGH into a continuous tone.
- The model is SHA256-verified at build and boot; input and six output tensors, RAM, and frame length/timestamp are checked. Alerts are enabled only after a valid inference completes.
- Camera/model startup failure enters `SAFE IDLE`, keeps GPIO14 LOW, reports the reason every 5 seconds and never reboots on its own. Five consecutive capture failures also enter safe silence.
- No beep during boot/model warm-up; there is no `delay(200)`/`delay(2000)`, the run loop yields only 1ms and error retries yield 100ms.

The confidence threshold and result validity live in `main/alarm_policy.hpp`. Raising the threshold reduces false positives but misses harder person poses; model detection is not absolutely reliable.

## Acceptance and real logs

1. On boot check `[HARDWARE]`, `[CAMERA]`, `[MODEL]` and confirm PID, PSRAM and that the model loaded.
2. Point at an empty, normally lit scene for at least 10 seconds: expect `No person` and no alert.
3. Walk in with the body as fully visible as possible: expect a person score and box plus a double beep; stay at least 10 seconds to check cooldown.
4. After leaving, it should return to silence. Power-cycle and repeat; it runs without a computer.
5. With other serial tools closed, record and summarize real on-board performance:

```sh
source scripts/env.sh
python scripts/capture_log.py /dev/cu.usbmodem5C930528211 docs/logs/acceptance.log --seconds 45 --reset
python scripts/analyze_log.py docs/logs/acceptance.log
```

`[FRAME]` reports preprocess, pure network inference, postprocess, frame acquisition and frame age separately, in ms. The summarized `Inference` includes preprocess+network+postprocess; official reference numbers are never presented as measurements.
Automated tests only verify alert policy, time boundaries, confidence filtering and model validation; they cannot replace real person/empty-scene acceptance.
This build and on-board validation record is in [docs/VALIDATION.md](docs/VALIDATION.md); raw records are in `docs/logs/`.

## Files

`main/app_main.cpp` handles hardware and the capture loop, `detector.cpp` runs the real model, `buzzer.cpp` handles RMT and the alert task, and `alarm_policy.hpp` is the independently testable alert policy.
`build/person_beep.bin`, `build/bootloader/bootloader.bin` and `build/partition_table/partition-table.bin` are build artifacts; normal flashing uses the scripts above and does not require manual addresses.
