Actual GPIO14 input readback is enabled. A complete double-beep example (microseconds):

```text
GPIO14 actual pad=1, t=20273863 us
GPIO14 actual pad=0, t=20473864 us
GPIO14 actual pad=1, t=20673863 us
GPIO14 actual pad=0, t=20873863 us
LOW, cooldown >= 2000 ms, t=20873863 us
```

Corresponding to HIGH **200.001ms** → LOW **199.999ms** → HIGH **200.000ms**. The pin readback task polls at 5ms; this is not an oscilloscope measurement, and the 200ms waveform is generated by the 1MHz RMT hardware.
When detection turns negative the running sequence is actively cancelled, so the log also contains pulses shorter than 200ms. Cancellation still requires the full cooldown.
The last ~15 seconds of the test were entirely `No person` with no new alerts. Real person entry/exit and the audio experience were confirmed successful by the user on site; software logs alone cannot prove sound or actual image content.

## Usage and reproduction

The main entry is `main/app_main.cpp`. Open the whole `person_beep` folder in VS Code and press **⌘⇧B** to build; Terminal → Run Task offers `ESP32: Flash` and `ESP32: Serial Monitor`.
You can also run `scripts/build.sh`, `scripts/flash.sh`, `scripts/monitor.sh` in a terminal as described in the README.

Build, flash and static-test logs are in `logs/`. Camera unplug/replug, corrupted model and PSRAM faults were not physically injected; those error branches were checked by code review and alert-policy unit tests, and no hardware fault injection is claimed.
The first 1MB of the original firmware and the complete app0 were backed up and verified; recovery steps are in `../backups/README.md`.
